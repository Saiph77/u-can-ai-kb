# 剪辑单：有素材，照着剪

产出物是一份剪辑清单，不是文章。读者是剪辑师或下游的剪辑 agent。它的全部价值在于：拿着上面的文字能在字幕文件里搜到、能在时间轴上定位到那一帧。

## 铁律：一个字都不能改

引用块里的每一个字，必须是逐字稿里的**精确连续子串**。不改写、不润色、不补标点、不修口误、不把不相邻的两句拼在一起。

口误和重复词看起来很碍眼——"我因为我是我主要做的是"、"学学学文学的"、"他就他不是"。忍住。这些在视频里听起来是正常的说话节奏，观众根本不会注意。但只要你把它们修顺了，字幕就和原声对不上，口型也对不上，整段作废。

**最容易破功的地方是摘金句。** 整段引用时人不太会动手，一到摘字幕卡点句就会不自觉地压缩：把"他的创作主题，加上颗粒，再加上技能或者叫技巧"压成"主题 + 颗粒 + 技能"，更上口，也彻底没用了。这类错误肉眼几乎发现不了，因为它读起来完全通顺。

所以：

```bash
python scripts/verify_verbatim.py <剪辑单.md> <逐字稿> --strict
```

**这一步不是可选的。** 脚本会抽出剪辑单里所有引用块和反引号短语，逐一去原稿做子串匹配，对不上的会告诉你从第几个字开始分岔、原稿实际写的是什么。`--strict` 还会额外检查每个短语在原稿中是否唯一——出现多次的短语做定位串会让剪辑师跳到错的地方。

跑到全绿再交付。把校验结果写进交付物开头（"N 条引用全部逐字一致，零处改动"），下游 agent 看到这行才知道可以信任这份文件。

## 时间码：两种精度，绝对不能混

逐字稿只在每段开头给一个时间戳，没有结束时间。于是：

- 片段边界正好落在某段的**开头或结尾** → 这是转写工具给的真实时间，可以直接信任。
- 片段从某段**中间**切入或切出 → 只能按段内字符位置线性插值估算，误差通常正负 2 秒。

这两种必须在交付物里分别标注（脚本会自动标）。混着给，下游会误以为所有时间码都精确到秒，然后在插值边界上剪出半个字。

**对插值边界，一律以 IN/OUT 原话为准去搜字幕定位，时间码只当跳转用。** 这句话要写进交付物。

算时间码用：

```bash
python scripts/transcript_index.py cut <逐字稿> --spec spec.json --quotes
```

spec.json 描述每个片段从哪到哪：

```json
{
  "offset": "00:29:37",
  "segments": [
    {"id": "A", "name": "片段主题",
     "from": {"line": 13, "after": "因为我对于内容的理解是什么"},
     "to":   {"line": 17}},
    {"id": "B", "name": "另一段",
     "from": {"line": 25, "after": "ai 时代内容已经不值钱了"},
     "to":   {"line": 33, "until": "我先拿做演示，比较方便"}}
  ]
}
```

`after` / `until` 省略就是从段落边界进出（真实时码）。写上就是段内截取（插值）。脚本会校验这些子串确实存在，不存在直接报错——所以它同时也是一道防改写的关卡。

`--quotes` 会顺便把逐字引用块打出来，直接贴进交付物，比手抄安全。

## 尽量少剪，尽量长

每一次跳切都是剪辑成本，也是观感上的一次颠簸。

**剪辑单位是"原稿中一段连续的话"，不是句子。** 句内碎剪会让语气断掉，听起来像拼贴，剪辑师也做不干净。一句一句挑着剪出来的东西，观众会明确感到不自然，哪怕说不出为什么。

好的剪辑单长什么样：五六个片段，最短的也有二十秒，其中有一两个是两三分钟的连续块，片段之间跳切三到五次。差的剪辑单：二十个片段，每个八秒，跳切十九次。

如果你发现自己在为了塞进某个观点而切出一个五秒的片段，通常说明这个观点应该整个放弃。

**微剪建议单独列，不要混在主时间码里。** 有些整句级别的插叙（跑题的一段、说了两遍的话）切掉会更紧，但那是可选优化。写成"可做可不做"，给出起点和终点原话，让剪辑师自己决定。永远不要建议句内碎剪。

## 交付物结构

```markdown
# 剪辑单：<主题>

**成片时长 X 分 Y 秒（原速）｜ N 倍速约 Z 分｜ 全片 M 次跳切**

## 给剪辑 agent 的说明
  - 这是纯逐字稿推导的毛坯，我没看过视频，边界对不上一点是正常的
  - 最终判断权在你手上，跟视频冲突一律以视频为准，不用回来确认
  - 引用块里每个字都必须能在逐字稿里逐字找到，不要改写
  - 逐字校验结果：N 条全部一致，零处改动
  - 两种时间码精度的区别

## 时间码怎么用
  - offset 假设是什么，怎么校正

## 剪辑总表（播出顺序）
  | 片段 | 成片时间 | 视频内时间 | 原稿时间 | 时长 | 内容 |

## 每个片段
  IN 点 / OUT 点（原话，可搜索）
  段落时间码表（含精度标注）
  > **[L行号]** 逐字原话
  可做可不做的微剪
  字幕卡点建议（也必须是原话）

# 可选加片段
  标注插在哪、加多少时长、加了会有什么问题

# 编辑说明
  为什么这么排、为什么开场用这段、整段放弃了什么、为什么
```

**「编辑说明」不是客套。** 下游 agent 看到画面后会想改结构，它需要知道你当初为什么这么排，才能判断哪些可以动、哪些动了会塌。特别要写清楚你放弃了什么以及理由——否则它会以为你漏了，然后把你故意砍掉的东西加回去。

## 播出顺序不等于原稿顺序

直播和访谈是被提问牵着走的，顺序基本随机。剪成视频后观众没有提问权，只能跟着一条线走，所以必须重排。

重排时优先考虑：

**先破后立。** 开头放一个反直觉或者得罪人的判断，中间给出解法，结尾升华。

**自我反驳很珍贵。** 如果说话人在某处推翻了自己刚说的话，那段几乎一定值得留——观众对"这人在真的思考"极其敏感。但要注意它会不会把主线带偏。带偏了就单独做一条。

**结尾用情感落点，不要用总结。** 摘要式的结尾没人记得住。找那句他一笔带过的、带着旧伤或者顿悟的话。

**检查衔接。** 重排之后，每个片段的第一句话都要能接住上一段的最后一句。特别注意以"因为""所以""那"开头的句子——它们原本承接的内容可能已经被你剪掉了。有时候只需要把 IN 点往前挪一两句，衔接就顺了；有时候需要把中间那段一起带上，反而更省事。

## 常见的坑

**屏幕演示。** 说话人指着屏幕说"你看这里""我给你们看一下"，脱离画面完全听不懂。这类段落整段放弃，除非剪辑师确认能配上录屏。

**主持人插话。** 用脚本的 `--speaker` 过滤，确认片段范围内没有混进别人的话。

**同一个观点讲了两遍。** 长直播里很常见。挑讲得更完整的那一次，另一次放弃。如果两次都用了，观众会觉得啰嗦。

**offset 是个假设。** 除非用户明确告诉你视频起点，否则「视频内时间」这一列是推算的。在交付物里显式写出这个假设和校正方法，别让它默默地错下去。
