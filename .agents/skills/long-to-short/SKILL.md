# 长素材剪成短视频

一份四十分钟的逐字稿，要变成五分钟能发的东西。这个 skill 处理的是从原始转录到可交付物料之间的那一段。

## 开工第一件事：问有没有原始素材

这个问题决定了后面每一条规则，而且两条路的规则是**相反的**。搞错方向，做出来的东西直接作废。

**有素材，要照着剪** → 产出剪辑单。**一个字都不能改。** 所有文字必须是逐字稿里的精确子串，因为剪辑师（或下游的剪辑 agent）要拿这些文字去搜字幕文件定位帧。改一个字，那句话就搜不到。→ 读 `references/cut-list.md`

**没素材，或者本来就要重录** → 产出口播稿。**必须改写。** 照抄逐字稿的口误、重复词、指着屏幕说的话，念出来会非常怪。→ 读 `references/spoken-script.md`

如果用户没说，直接问。不要猜。这个 skill 存在的原因之一就是：曾经有人默认走了重录那条路，交出一份润色得很漂亮的稿子，而用户手上有视频——那份稿子里的话他一句都没说过，全部作废。**问一句的成本远低于返工。**

偶尔两个都要（先剪一版，同时备一份重录稿）。那就分成两个文件做，不要混在一起，因为逐字忠实和自由改写这两套规则放进同一份文档必然互相污染。

## 通用第一步：先摸清素材

不管走哪条路，先跑这两条命令，别上来就读稿子。

```bash
# 段落时间码索引：每段的起止、时长、字数、语速
python scripts/transcript_index.py index <逐字稿> --offset HH:MM:SS

# 语速实测。写口播稿换算时长时用这个数
python scripts/transcript_index.py stats <逐字稿> --speaker <说话人>
```

语速这件事值得单独说：不要用"中文 250 字/分钟"这类通用经验值。实际语速在 250 到 400 字/分钟之间浮动，个体差异巨大。用错基准，五分钟的稿子写出来能变成七分钟。**先测，再写。**

`--offset` 是逐字稿时间码和视频文件时间码之间的差。如果逐字稿是从一场更长的录制里截出来的中段，第一句话的时间戳可能是 `00:29:37` 而不是 `00:00:00`。把这个值填进去，脚本会同时输出「视频内时间」。这个偏移量通常没法从逐字稿本身确定，**要向用户确认，或者在交付物里明确标注这是个假设**。

## 编辑判断：这个 skill 里唯一不能自动化的部分

脚本能算时间码、能校验逐字、能统计语速。选哪几段、按什么顺序排——只有你能做，而这才是全部价值所在。

**第一原则：你的判断体现在你选择不用什么。** 四十分钟里可能有十五个话题，值得进片的可能只有四个。不要给每个话题平均分配时长。判断标准不是"他讲了多久"，而是"这段话是否改变了我对某件事的理解"。讲了十五分钟但没产生新判断的话题，一秒都不给。

**第二原则：先找原素材里最长的连贯块，再围绕它搭结构。** 这一条反直觉，但极其有用。人在真正进入状态时会连续讲上三五分钟，逻辑自洽、不用剪。这样的段落是整条视频的地基——它同时解决了内容质量和剪辑成本两个问题。先扫描出这样的块，再决定前面垫什么、后面收什么。反过来做（先设计好结构再去素材里凑）会得到一堆两三句话的碎片，剪起来痛苦，看起来也跳。

**第三原则：最有分量的话，说话人往往一笔带过。** 新鲜的观点他会展开讲，因为他自己也还在兴奋。但那些他早就想通了的、构成他底层判断的东西，他只会顺口提一句就过去——对他来说那不是新闻，是常识，甚至是旧伤。这类句子经常是整条视频最好的结尾。扫稿子时专门找那种「一句话信息量极大但他没停下来」的地方。

**第四原则：开场不要从背景介绍开始。** 从最反直觉的判断、最强的身份反差、或者最得罪人的一句话开始。观众前三秒决定要不要划走。

## 收尾：交给下游的时候要说清楚

不管产出什么，最后都要交给人或者另一个 agent。有两件事必须写进交付物：

**这是毛坯，不是定稿。** 你只看过逐字稿，没看过视频。机器转录有时间码漂移、断句不准、看不出他什么时候在指屏幕、听不出语气和停顿。下游 agent 能看到画面，判断权在它手上——凡是你给的切点跟视频实际情况冲突，一律以视频为准，不用回来确认。

**明确哪些数是可信的、哪些是估的。** 详见 `references/cut-list.md` 里关于两种时间码精度的说明。混着用会让下游误以为所有时间码都精确到秒。

## 目录

```
long-to-short/
├── SKILL.md                      本文件：分路 + 编辑判断
├── references/
│   ├── cut-list.md               有素材 → 剪辑单（逐字忠实）
│   └── spoken-script.md          要重录 → 口播稿（自由改写）
└── scripts/
    ├── transcript_index.py       解析、索引、语速、时间码插值
    └── verify_verbatim.py        逐字校验，防止改写混进剪辑单
```

两个脚本都能直接 `--help`，也都支持常见的逐字稿格式（`说话人(HH:MM:SS): 文本`、`[HH:MM:SS] 文本`、SRT、VTT）。碰到没见过的格式，先看 `transcript_index.py` 顶部的 docstring，多半只需要加一条正则。
