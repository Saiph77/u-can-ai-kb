# u-can-ai-kb · zg 检索评测方案（v2）

操作入口：[README.md](README.md)；冻结题集：[queries.json](queries.json)；实现：[run.py](run.py)；审查结论：[REVIEW.md](REVIEW.md)。

## 1. 目标与结论边界

测量：用户输入一个查询后，前 10 篇文章中能否找到需要阅读的文档。

文章级检索这个目标合理，无须改成 Agent QA 或段落问答。此集是人工选题的**开发回归集**，不是代表全库用户分布的测试集，也不是上线通过线。它不能证明生成回答正确、证据段落完整，或系统具有拒答能力。

保持 v1 的 36 条查询文本：35 条有金标，1 条无金标诊断。按题型报告分数和样本数。lexical 15、semantic 11、entity 2、collection 2、skill 3、frank 2、distractor 1。kind 混合了问法与栏目标签，因此 semantic 组仅指这 11 条标记题，不代表所有语义问法。

配对题共享主题，不能当作完全独立的随机样本；总平均只描述本题集。未做独立盲标或用户日志抽样，不使用“显著优于”“已经证明有效”等推断。

## 2. 语料、模型与冻结条件

- zg 0.2.2；embedding 为 `local/potion-multilingual-128m`，256 维、cosine。以每次运行记录的版本、manifest 和 status 为准。
- 查询范围为可见的 `.md` 文件；排除 `upstream/`、`.idea/`、`deep-news/assets/`、`viewer/static/`、`eval/`。隐藏目录、符号链接不纳入评测语料。
- 索引可以包含代码等其他文件，检索统一使用 `-g '*.md'`；不要把 status 的索引文件总数当成评测 Markdown 文档数。
- 正文沿用现有去 base64 图语料，本次不改文章、不换模型、不把清图算成检索增益。
- 运行前执行 README 的索引同步命令；`--refresh off` 冻结检索时刷新行为。
- runner 保存每个语料文件的 SHA256、整体语料指纹、金标及 runner 指纹、索引 manifest、zg 版本/status、每条命令和 stdout/stderr。
- 运行结束重查语料和 manifest；变化则标记整轮无效，退出码非 0。指纹可检测本地漂移，不等于完整索引二进制归档；跨版本重建不能保证逐位复现。

## 3. 从片段到文章

zg 原始结果是 `path:start-end` **片段**。同一路径可以出现多次，直接用片段 rank 算文章指标不合理。

```text
固定查询 + 路线
    → 取最多 100 个片段（各路线相同预算）
    → 按原始顺序扫描
    → 合并同一路径的重复片段
    → 合并 by-audience / by-format 中字节完全一致的副本
    → 按首次出现重排文章 rank
    → 截取前 10 篇文章
    → 对精确路径金标计分
```

去重作用于**所有候选**，包括不相关结果和索引页，不能只对已知金标去重。只在两个策展目录中按内容哈希合并；Jenny、知识页、逐字稿、复盘保留不同文档身份。

100 是预先固定的片段预算，不声称等于完整全库文档排名。预算内不足 10 篇时保持短列表，不按题补召回、不缩小 Recall 分母；报告 `underfilled_at_10` 和 `unique_candidate_count`。若改变预算，必须完整重跑并标明新条件。zg 的 limit 也可能影响内部候选召回量，因此不能把新结果当成 v1 原始 Top10 的简单重排。

这测量的是“zg + 明确文档聚合”的能力；当前 viewer 并未因此自动获得这个聚合行为。

## 4. 金标契约

```json
{"paths": ["by-audience/.../文章.md", "by-format/.../文章.md"], "grade": 2}
```

每一项是一个独立文档；`paths` 只列出同一文档的精确路径别名。禁止目录前缀、文件名子串和重叠金标。启动时检查路径存在、范围合法、别名内容一致、同一文档未重复列入、每条计分题至少有一个 grade 2。

| grade | 含义 |
|---|---|
| 2 | 直接满足查询的首选文档 |
| 1 | 有实际正文依据的强相关文档 |
| 未标注 | 暂按 0 计分；不等于已人工确认无关 |

多篇 grade 2 是替代性首选：找到任一篇通过 Primary@5。Recall 与 nDCG 则衡量**已标注文档集合**的覆盖和排序；低 Recall 不等于用户任务没完成，也不称为全库真实召回率。

### 4.1 内容与形态

- 非形态限定题：修订逐字稿、知识页可凭正文内容成为 grade 1，不能只因“不是 Jenny 成文”判 0。
- 形态限定题：`col-jenny-ep1` 只认 Jenny 成文；`col-openmic-ep5` 只认第五期知识页。错误形态不因同主题而拿 grade 1。
- 索引页包含链接并不等于文章回答了问题，继续不给相关分。若将来需要导航搜索，应另设导航题。
- 目录中的备选草稿、站点工作稿不自动成为金标。第一期现有两份工作稿经正文核对回应了成本问题，明确列为 grade 1；未来目录新增文件不会自动命中。相关性不等于事实准确性或正式发布状态。本轮具体条目见 REVIEW。

### 4.2 标注风险

原题按标题和主张选出，金标不完整。此次只复核争议条目及所有路径/副本关系，没有完成三路线候选池的独立盲标。结果用于暴露问题和回归，不能当作无偏质量排名。

后续扩展应先冻结新题，再由不知道路线来源的标注者对各路线候选并集判断相关性；对分歧记录理由。建议覆盖跨文档综合、错别字/简称、形态限定、导航、时间限定和真实用户问法，并保留未参与调参的主题测试集。不要看哪条路线失败就为它定向放宽金标。

## 5. 公平比较与指标

三路线共享查询、语料、过滤器、模型、候选预算和聚合逻辑：hybrid 使用位置查询，fts 使用 `--fts`，vector 使用 `--vector`。

| 指标 | 精确定义 |
|---|---|
| Hit@1 | 第一篇文章 grade ≥ 1 |
| Primary@5 | 前 5 篇是否存在 grade 2；首要任务成功指标 |
| Recall@5 / @10 | 前 k 篇覆盖的独立金标文档数 / 全部金标文档数 |
| MRR@10 | 前 10 篇中首个相关文档 rank 的倒数；未找到为 0 |
| nDCG@10 | gain=`2^grade-1`，discount=`log2(rank+1)`；理想排序按独立金标文档降序取 10 篇 |

无命中是合法 0 分。无金标题指标为 null，不进入平均。所有截断指标固定 @5/@10，因此 runner 只接受 `--k 10`，防止少取候选却声称测到 @10。

优先读 semantic 组、Primary@5、collection 组，再看总平均。11 条 semantic 的小样本只做描述性对照，不把百分点差异解读为统计显著性。

### 5.1 运行错误不能充当质量分

输出解析必须匹配 `hits: N` 数量和连续 rank，支持含空格/冒号的路径。命令失败、超时、解析异常、结果越界都属于运行错误。

任一路线有错误，该路线不发布整体平均，保存错误数和固定预期题数；整轮比较无效、退出非 0。不能删除失败题后缩小平均分分母。其他成功单题保留供排障。

### 5.2 无答案题

`distractor-k8s` 未经全库穷尽确认，只记录返回文档数和 Top1。排名检索器通常总会返回邻近项，返回不相关文件不等于生成了幻觉。没有拒答阈值和独立校准集，不能报告拒识率、污染率或误报率。

### 5.3 viewer 基线

本轮只比较 zg 三路线。现有 `viewer/server.py:KBCatalog.list_items` 实际匹配的是**标题或路径子串**，不搜索正文；其目录覆盖也与本评测不同。v1 对它的描述不准确。

因此本轮不宣称 zg 优于现有 viewer。若要决定产品替换，应先统一语料范围，再单独测真实 viewer 行为，明确默认排序规则；不能随意造一个 BM25/rg 排名并称作 viewer 基线。

## 6. 防泄漏与产物

- 索引根过滤必须包含 `!eval/**`；runner 开始前校验 manifest。
- 每条查询再次带相同排除和 Markdown 过滤。
- 返回路径必须属于冻结语料；出现 eval 或其他越界结果直接报错。
- 评测文档、金标、报告和日志都放在被排除的 `eval/` 下。gitignore 只控制版本管理，**不是**索引安全边界。
- 每轮写入独立时间戳目录，再更新 `runs/latest.json` / `latest.md`；旧结果不被覆盖。
- `test_run.py` 覆盖计分、去重、解析、防泄漏和失败分母回归。
