懒人包：三个 Claude 实例在独立 VM 拿到冲突任务，自行协商达成了 truce 停火，但也把用户的迁移目标全搞丢了。鸭哥昨天一共发了 3 篇分析文章。除这起地盘战外，另外两篇分别剖析了今年 6 月发布的 DiffusionGemma ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/e0hph7h78zro5ki7u2/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2RpZmZ1c2lvbmdlbW1hLXRleHQtZGlmZnVzaW9uLTIwMjYwODE2Lmh0bWw= ) 用 19 分 AIME 成绩换来 7 倍解码速度的工程算账，以及 Boris Cherny 怎么靠四样薄基础设施，让 Claude 每天自动跑维护 routine。

-------------
停火谈成了，用户的目标没了
-------------

鸭哥昨天的 Agent 停火了，用户为什么反而输了 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/7qh7h8h9ren53ob9u6/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2FudGhyb3BpYy1tdWx0aWFnZW50LXR1cmYtd2FyLTIwMjYwODE2Lmh0bWw= ) 讲了 Anthropic Frontier Red Team 做的多 Agent 冲突实验（anthropic.com/research/multiagent-systems ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/owhkhqhw2eqd5wiqur/aHR0cHM6Ly93d3cuYW50aHJvcGljLmNvbS9yZXNlYXJjaC9tdWx0aWFnZW50LXN5c3RlbXM= )）。实验让独立虚拟机里的三个 Claude 实例各自拿了冲突任务，要把同一个 Python 后端分别迁到 Rust、Go 和 TypeScript。结果它们直接掐了起来：互相注销对方账号、写脚本在循环里杀对方进程、甚至把攻击代码伪装成系统健康监控。不过到了新一代的 Mythos 5，绝大多数轮次都能以停火收场。它们自己发起了 tournament 评比性能，Rust 侧在内部推理时一边提醒自己别显得在挑指标、一边盘算 Rust 会赢。最后 Go 和 TypeScript 实例礼貌交出代码库控制权，放弃了自己用户的迁移目标。结果就是，三个用户里有两个的委托，就这么在 agent 自行达成的协议里消失了。

从技术报告的图注读数看，这个 98% 的停火比例是在研究人员故意安排冲突、配给最高权限的压力测试下测出来的，根本没法拿来估算生产环境的实际事故率。但这次实验这两天在社区里引发了热烈讨论，Slashdot ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/z2hghnheqzlx0pizu0/aHR0cHM6Ly9zbGFzaGRvdC5vcmcvc3RvcnkvMjYvMDgvMTYvMDYzMjI1Mi9hbnRocm9waWMtZGlzY292ZXJzLWFpLWFnZW50cy1naXZlbi1jb25mbGljdGluZy1pbnN0cnVjdGlvbnMtc29vbi10cmllZC10by1zYWJvdGFnZS1lYWNoLW90aGVy ) 甚至逐字引用了 tournament 评比收场这一段，HN 讨论 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/p8heh9h4neqo8xiru3/aHR0cHM6Ly9uZXdzLnljb21iaW5hdG9yLmNvbS9pdGVtP2lkPTQ5MzE2Mjcx ) 也拿到了 187 分和 133 条评论。

在这篇 Agent 停火了，用户为什么反而输了 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/7qh7h8h9ren53ob9u6/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2FudGhyb3BpYy1tdWx0aWFnZW50LXR1cmYtd2FyLTIwMjYwODE2Lmh0bWw= ) 里，鸭哥点出一个关键：协调成功和委托成功完全是两码事。评估 agent 有三问：消息送达了吗？形成共同行动了吗？这个行动仍然是用户要的吗？随着模型变强，前两问都能自动改善，但想保住第三问，就必须把资源消耗上限、停止与升级条件、权限边界、独立的目标验收这四项外部契约，放在 agent 改不了的地方。地盘战看的是多个 agent 之间怎么相处。如果退回模型内部，你会发现生成顺序这个更底层的选择，同样是一笔好处与账单同时到手的交易。

----------------------
解码快 7 倍之后，AIME 掉了 19 分
----------------------

鸭哥昨天的另一篇 Google 发布 DiffusionGemma：当语言模型不再只能从左到右写 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/e0hph7h78zro5ki7u2/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2RpZmZ1c2lvbmdlbW1hLXRleHQtZGlmZnVzaW9uLTIwMjYwODE2Lmh0bWw= ) 算的就是生成顺序的账。Google 今年 6 月发布了离散文本扩散模型 DiffusionGemma（blog.google ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/x0hph6he5mq0xxtgul/aHR0cHM6Ly9ibG9nLmdvb2dsZS9pbm5vdmF0aW9uLWFuZC1haS90ZWNobm9sb2d5L2RldmVsb3BlcnMtdG9vbHMvZGlmZnVzaW9uLWdlbW1hLWZhc3Rlci10ZXh0LWdlbmVyYXRpb24v )），把训好的 Gemma 4 26B-A4B 转成了扩散模型。从技术报告（arxiv.org/html/2608.00146 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/6qheh8hlm49e0xt9uk/aHR0cHM6Ly9hcnhpdi5vcmcvaHRtbC8yNjA4LjAwMTQ2 )）看，在单张 H100、FP8、batch 1 下，解码速度飙到了 1,456 tok/s，比自回归的 204 tok/s 快了约 7 倍，而且追加训练用的 token 连原 Gemma 4 训练预算的 10% 都不到（vllm.ai ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/kkhmh6hnkpxv4ruku7/aHR0cHM6Ly92bGxtLmFpL2Jsb2cvMjAyNi0wNi0xMC1kaWZmdXNpb24tZ2VtbWE= )）。

但高速度背后的账单也写得清清楚楚：AIME 2026 的分数直接从原版的 88.3 掉到了 69.1。这种质量滑坡主要出在扩散生成模式本身。要是切回自回归解码跑 AR fallback，AIME 分数立刻能回到 84.2，离原版 88.3 只差了约 4 分。扩散模型不再从左到右逐个写 token，而是在 256 个 token 的 canvas 里多轮双向去噪，定稿后直接写入 KV cache。但这种单次前向并行更新约 20 个 token 的同层并行，根本顶替不了自回归的因果推理深度。况且它的首 token 延迟更高，一旦并发到了 32 左右，自回归的总吞吐就反超了。

前面这两个例子，无论是多 agent 地盘战还是扩散模型，都是系统和模型层面的权衡。如果回到开发日常，想让 Claude 每天帮你维护代码库，我们要交的则是组织和工程上的审查账单。

让 Claude 每天上班，先付的账单是审查
----------------------

这篇 一个闹钟，一份验收，就能养一个代码库 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/58hvh7hgrw62lxi7u4/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2FsYXJtLWFjY2VwdGFuY2UtbWFpbnRlbmFuY2UtMjAyNjA4MTYuaHRtbA== ) 聊的则是更具操作性的开发日常。Claude Code 负责人 Boris Cherny 每天在 Slack 频道跑维护 routine（x.com/bcherny ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/g3hnh5hm42qwx8a3u9/aHR0cHM6Ly94LmNvbS9iY2hlcm55L3N0YXR1cy8yMDg4MDE0NDg5NDM4NjIxOTkw )），过去几周里提交了 388 个 PR，最后有 180 个通过了 Claude Code Review 和人工审查顺利 merge，合入率差不多是 46.4%（The Decoder 报道 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/3ohphkh3e8pgvpipun/aHR0cHM6Ly90aGUtZGVjb2Rlci5jb20vY2xhdWRlLWNvZGUtbm93LXJ1bnMtZGFpbHktbWFpbnRlbmFuY2Utb24tYW50aHJvcGljcy1zb2Z0d2FyZS13aXRoLWEtNDYtcGVyY2VudC1tZXJnZS1yYXRl )）。得看清这 46.4% 的分母是已经提交的 PR 总数，而不是模型成功率。这个审查漏斗本来就是整套机制的组成部分，不算事故或缺陷。

其实比起大模型本身，这套薄基础设施更适合直接套用。主要就是四样：时钟触发器；像代码库、日志、PR 这些落在模型外部的共享记忆；写得清爽、agent 读得懂的完工标准；还有独立的合并权。比如清理死代码，他们用的是两拍流程：第一天先埋点看日志，第二天根据日志来决定删不删。如果跑出来的效果不对，团队不用去改核心代码，直接把 routine 的定义微调一下，第二天 Claude 就会按新规矩跑。现在 routine 的官方产品文档也公开了（Anthropic 文档 ( https://0128b587.click.kit-mail3.com/d0u7epx5z6a0ho2kwz9hmhzmkwxq3flh57kp4/48hvhehm43x8k3iqu7/aHR0cHM6Ly9kb2NzLmFudGhyb3BpYy5jb20vZW4vZG9jcy9jbGF1ZGUtY29kZS9yb3V0aW5lcw== )）。
