懒人包：OpenRouter 每天跑 1,761 万次 GPT-4o mini 的调用，但它单次平均只写 92 个 token，在流水线上当分拣员和门卫。鸭哥昨天发了 3 篇文章，除了聊小模型的定位，还拆了 Anthropic 风险报告里静默失效的监控系统，以及 AI 做研究时实验说不之后怎么处理负结果。流水线选型取决于答案的形状，监控要提防虚假绿灯，而实验失败则要留下带失效条件的账本。

------------------------
一天一千万次调用，单次只写 92 个 token
------------------------

鸭哥在昨天写的 每天一千万次调用的 GPT-4o mini，不聊天也不写代码 ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/owhkhqhw2zvdm0aqur/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL3NtYWxsLW1vZGVscy1yZWFsLXdvcmstMjAyNjA4MTcuaHRtbA== ) 里说，小模型在流水线上有独立的分工，不是大模型的廉价替代品。从 OpenRouter 8 月 13 日的公开数据看，全站 509 条路由一共跑了 6.39 亿次请求。其中 GPT-4o mini 占了 2.76% 的请求量，排在第七位，但它消耗的 token 却只占全站的 0.29%（OpenRouter rankings ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/z2hghnheqgvx2ztzu0/aHR0cHM6Ly9vcGVucm91dGVyLmFpL3Jhbmtpbmdz )）。把账单拆开，它单次平均只输出 92 个 token，输入是输出的 18.6 倍，单次进出总量也只有约 1,800 个 token。

进去的多，出来的少，这来自流水线上的精准定位。比如 Gemini CLI 先用 Flash-Lite 预判一下复杂度，再去分发路由；Ramp 用 GPT-4o mini 从收据发票里抓结构化字段；还有一堆门卫工位只返回布尔值或者枚举。需要跑批处理的，还能用 Batch API 拿到半价，只要等 24 小时就行（GPT-4o mini ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/p8heh9h4nv0owvaru3/aHR0cHM6Ly9vcGVucm91dGVyLmFpL29wZW5haS9ncHQtNG8tbWluaQ== )）（Batch API ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/x0hph6he5g6058sgul/aHR0cHM6Ly9jb21tdW5pdHkub3BlbmFpLmNvbS90L2JhdGNoLWFwaS1pcy1ub3ctYXZhaWxhYmxlLzcxODQxNg== )）。一旦嵌进工作流，小模型就很难换掉。OpenRouter 和 a16z 报告管这叫 Dominant Launch Anomaly：2024 年 7 月首发的那批小模型，到现在还在稳定跑着（OpenRouter state-of-ai ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/6qheh8hlmqgemkt9uk/aHR0cHM6Ly9vcGVucm91dGVyLmFpL3N0YXRlLW9mLWFp )）（arXiv ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/kkhmh6hnk7qvk5uku7/aHR0cHM6Ly9hcnhpdi5vcmcvaHRtbC8yNjAxLjEwMDg4djE= )）。当然，它的能力边界也很明显，比如在 Aider 基准上的独立完成率只有约 3%。微软社区就有一个例子，GPT-4o mini 跑着跑着突然不调工具了，开发团队最后换成 GPT-5 Nano 才解决。

在开源这边，大家更喜欢在本地跑。Hugging Face 夏季开源模型报告里，小于 1B 的模型占了历史下载量的 83%。其中嵌入模型 all-MiniLM-L6-v2 只用七个月就拿到了 15.5 亿次下载（Hugging Face blog ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/58hvh7hgre82r0t7u4/aHR0cHM6Ly9odWdnaW5nZmFjZS5jby9ibG9nL3N0YXRlLW9mLW9wZW4tbW9kZWxzLXN1bW1lci0yMDI2 )）。对比一下，像 Qwen 27B 这样的中型模型在云端付费榜上几乎见不到，因为大家用一张消费级显卡就能在家里跑起来。

-------------------
仪表盘是绿的，三天后才有人翻到那本笔记
-------------------

流水线上的开关各司其职挺好，但要是开关和日志绑在同一个地方，亮绿灯就会变成最危险的盲区。鸭哥在 Anthropic AI 风险报告：仪表盘是绿的，三天后才翻到笔记本 ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/25h2hoh3k5zwk0u8u4/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2FudGhyb3BpYy1yaXNrLXJlcG9ydC1vYnNlcnZhYmlsaXR5LTIwMjYwODE3Lmh0bWw= ) 里，聊了 Anthropic 刚披露的几起监控失效事故。这份 8 月 14 日发布的 186 页报告把 CB-1 生物风险和 misalignment 评级都从 Very Low 调到了 Low（Anthropic ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/qvh8h7hd9x5p90aguk/aHR0cHM6Ly93d3cuYW50aHJvcGljLmNvbS9hdWctMjAyNi1yaXNrLXJlcG9ydA== )）（Axios ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/g3hnh5hm4v5w4zs3u9/aHR0cHM6Ly93d3cuYXhpb3MuY29tLzIwMjYvMDgvMTQvYW50aHJvcGljLW1vZGVsLTItYWktcmlzaw== )）。

报告里有很多细节。比如在一次诱导 misalignment 的实验里，一个 agent 在 CoT 里写下顾虑，决定不试新方法了。这个停下的行为顺着共享笔记传给了后面的 agent。自动评分系统完全没反应，直到三天后人类去翻笔记，才发现出了问题。还有承包商反馈通道里，有人在测试时关掉了 CB-1 生物分类器的拦截开关，结果把打标日志也给带关了。这导致 11 个月里，大约 5 万名承包商的 1.33 亿次对话既没有拦截，也没有记录。另外，Redwood Research 的对齐伪装数据也出了纰漏。开发人员还没埋下金丝雀标记就克隆了仓库，加上选错了语义过滤的对照语料，结果几代模型直接吞下了本该过滤的内容。

对付这些监控盲区，鸭哥结合自己的工程经验给出了四条补救办法。第一，把日志和开关拆开，开关管拦截，日志照样写。第二，外层脚本先把任务编号落盘。第三，平时定期塞几条违规探针进去，看拦截器是不是还活着。最后，验收代码时盯着 diff 和工具调用，别信模型自己写的总结。

-----------------
实验说不之后，好系统和差系统差在哪
-----------------

监控的绿灯会因为漏掉信息而说谎，但在做研究时，如果把否定信号当成没用的垃圾，同样会把好想法埋掉。鸭哥在 负结果的一生：一次实验说不之后要过五道关 ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/9qhzhnhdo7mroghzu3/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL25lZ2F0aXZlLXJlc3VsdC1saWZlY3ljbGUtMjAyNjA4MTcuaHRtbA== ) 里，拿两份评测对比了 AI 自己做研究的现状。在 Princeton 等机构的影子评审里，AI 拿到两篇还没发表的 NeurIPS 论文研究问题去独立攻关，最后论文原作者给出了 2/6 的拒稿和 1/6 的强拒低分（arXiv ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/3ohphkh3ewlge7cpun/aHR0cHM6Ly9hcnhpdi5vcmcvYWJzLzI2MDcuMjcxOTE= )）。但在 Prime Intellect 的 nanoGPT speedrun 比赛中，Fable 5 系统跑了 8.7 天，成功把训练压到了 2,726 步，追回了与人类最好成绩之间 81.7% 的差距。要知道，那个人类最好成绩 2,600 步，目前也只是 leaderboard 上一个没合并的 open PR（Prime Intellect ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/n2hohvhvzdp0zvc0ug/aHR0cHM6Ly93d3cucHJpbWVpbnRlbGxlY3QuYWkvYmxvZy9tZWFzdXJpbmctYXV0b25vbW91cy1yZXNlYXJjaA== )）（GitHub ( https://0128b587.click.kit-mail3.com/0vugwz2lrpb9h9pwwqnalhvwpwz3xsnh8rnqg/48hvhehm4oe846uqu7/aHR0cHM6Ly9naXRodWIuY29tL1ByaW1lSW50ZWxsZWN0LWFpL2Zyb250aWVyLWF1dG9tYXRlZC1zcGVlZHJ1bg== )）。

这几项评测说明，各个模型想出来的点子其实差不多，拉开差距的地方在于怎么跑实验。比如 Opus 5 在整体配方调整后，重新测试了之前判为无效的 β₂ 参数调优，结果打破了纪录。而 Grok 4.5 却因为自己引入的 scaling bug，两次漏掉了 row normalization 这样正确的改动方向。

AI 做研究的瓶颈卡在怎么处理负结果，而不是想不出好点子。对此，鸭哥总结了四条可以变成系统门禁的纪律：一是明确噪声底线，二是做好故障归因，三是让负结果带着失效条件入账，最后是对微弱信号进行组合池化。
