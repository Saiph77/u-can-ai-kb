懒人包：xAI 给消费端 Grok Bot 配了八个带岗位的 AI 同事，但鸭哥翻它自家工程工具 Grok Build 的运行日志，看到的子 agent 全叫 researcher-0、evidence-verifier 这样的功能名，一个 persona 都没有。昨天鸭哥发了 2 篇 AI 文章，第一篇 卖你 AI 产品经理的公司，自己的 agent 不设岗位：multi-agent 的角色、隔离与代码 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/3ohphkh3p60orkfpun/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL211bHRpLWFnZW50LWhhdHMtbGF5ZXJzLTIwMjYwODE4Lmh0bWw= ) 把岗位包装下的机制翻出来看，第二篇 Btrfs 从零讲起：一个写盘动作换来的能力和账单 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/n2hohvhv7wm8g4h0ug/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2J0cmZzLWRlc2lnbi1zdG9yeS0yMDI2MDgxOC5odG1s ) 用一个底层写盘动作讲完能力与账单。当天 OpenAI 在安全事件后整改，Stripe 收购 OpenRouter，阿里巴巴开源了 Qwen3.8。

卖帽子的公司，自己不戴帽子
-------------

鸭哥在 卖你 AI 产品经理的公司，自己的 agent 不设岗位：multi-agent 的角色、隔离与代码 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/3ohphkh3p60orkfpun/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL211bHRpLWFnZW50LWhhdHMtbGF5ZXJzLTIwMjYwODE4Lmh0bWw= ) 里拆了这三种坐法。xAI 8 月 11 日开启 Grok Bot 的 early beta，官方列了销售外呼、报销对账等八个岗位（xAI 公告 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/wnh2hghq09n5v9alux/aHR0cHM6Ly94LmFpL25ld3MvaW50cm9kdWNpbmctZ3Jvay1ib3Q= )）（官方文档 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/reh8hohm6942v2s6u6/aHR0cHM6Ly9kb2NzLnguYWkvZ3Jvay1ib3QvdXNlLWNhc2Vz )）。不过社区反应冷淡，HN 主帖只拿到 59 分，没多久就被 flag 掉了（HN ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/08hwh9h2l0vow9upu5/aHR0cHM6Ly9uZXdzLnljb21iaW5hdG9yLmNvbS9pdGVtP2lkPTQ5MjYxNTMy )）。第三方的实测也说明，Grok Bot 所有同事其实共享同一台云电脑，cookie 和本地凭证互通，根本没有权限隔离这回事（Substack 评测 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/8ghqhohorez0p3hlu9/aHR0cHM6Ly9uYXRlc25ld3NsZXR0ZXIuc3Vic3RhY2suY29tL3AvZ3Jvay1ib3QtcmV2aWV3 )）。

帽子只住在给用户看的接口层，机制层并不认它。提升输出质量的关键在于给模型干净且互不干扰的 context window，角色帽子帮不上忙。打个比方，把十家竞品的信息全塞进同一个 prompt，最后出来的报告虽然格式工整，内容却互相稀释，流于平庸；如果把它们拆开分给十个干净的窗口处理，最后由主线程汇总，哪怕不派任何角色，产出效率也能上去。

xAI 自己的工程工具 Grok Build 在跑 deep-research 工作流时，就完全不戴帽子。Grok Build 的内核里把活拆成规划、检索、验证、成稿四个阶段，归八个干粗活的子 agent 协同管：一个 research-planner、负责检索的 researcher-0 到 researcher-3、两个证据核对 evidence-verifier，以及写报告的 report-synthesizer。这套系统默认开四路检索，放开 128 个 agent 总预算和 32 个并发上限，还支持 journal 文件断点恢复。生成报告前，24 条候选断言要让两个独立 verifier 各校对一遍，全部通过才能写进报告。

编排席的坐法决定了控制权属谁。这三把椅子，第一种是 Grok Bot 这种委派直觉的队友人格模式；第二种是 Codex、Cursor 和 OpenHands 采用的主 agent 模式，下一步由当前 agent 拍板，开发者只能靠提示词调优来引导其判断倾向；第三种则是脚本模式，比如 Claude Code 在 5 月 28 日发布的 dynamic workflows，允许模型在 runtime 现写 JavaScript 去编排几十上百个 subagent（官方文档 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/vqh3hrhow2lx33uwul/aHR0cHM6Ly9jb2RlLmNsYXVkZS5jb20vZG9jcy9lbi93b3JrZmxvd3M= )），Grok Build 跑 /deep-research 背后用的也是 Rhai 脚本。

这套分层不是新鲜事，2023 年的 MetaGPT 就试过把软件公司的 SOP 硬编码进角色里（arXiv ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/l2hehmhlx5e0vzigu0/aHR0cHM6Ly9hcnhpdi5vcmcvYWJzLzIzMDguMDAzNTI= )），是岗位即机制的早期范本。当下即便在 Claude Code 这种把接口层改叫 teammate、能点对点发消息的系统里，机制层核心也是一份共享的 tasks.md 账本文件。Grok Bot 官方虽然只列了 Chief of Staff 角色（官方文档 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/reh8hohm6942v2s6u6/aHR0cHM6Ly9kb2NzLnguYWkvZ3Jvay1ib3QvdXNlLWNhc2Vz )），但鸭哥在文章里指出它管周报的那个同事叫 Piper。OpenAI Codex 的 multi-agent V2 在 CLI 0.145.0 标为 stable 后（官方文档 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/m2h7h5h34kvg0nfluq/aHR0cHM6Ly9kZXZlbG9wZXJzLm9wZW5haS5jb20vY29kZXgvc3ViYWdlbnRz )），也把 slot 释放和 LRU 驱逐等控制权从模型决策移进了 runtime（源码分析 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/dpheh0hepzv4wqslu4/aHR0cHM6Ly94LmNvbS96YXRzL2FydGljbGUvMjA3NTc4ODc4NzQ4NTk3ODc2MQ== )），用确定性代码取代了模型猜测。

盯住底层的写盘动作
---------

这套读法不挑对象，把镜头从编排层挪到磁盘上，Btrfs 也能用同一个动作读明白。鸭哥在 Btrfs 从零讲起：一个写盘动作换来的能力和账单 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/n2hohvhv7wm8g4h0ug/aHR0cHM6Ly95YWdlLmFpL3NoYXJlL2J0cmZzLWRlc2lnbi1zdG9yeS0yMDI2MDgxOC5odG1s ) 里，把 Btrfs 的花哨特性和历史老账全收拢回了一个底层的写盘动作：写时复制（CoW）。

Btrfs 的全部脾气都来自写时复制：修改文件先写在空白盘区，写完再把指针拨过去，旧内容原地不动。这个动作给它买来了低到近乎免费的快照成本，创建快照（基于 subvolume）只需要建一个树根指针，不用搬运哪怕一个字节。数据落盘还会顺带存校验值，读取时重算，对不上就直接报错，防止坏数据混进备份链。

但这动作为系统签下了高昂的账单：频繁改写会导致文件碎片化，拖累数据库和 VM 镜像的性能；磁盘里又分了 1GiB 数据块组和 256MiB 目录块组两本账，经常碰到明明有空间却写不进数据、甚至连文件都删不掉的窘境。另外，要是为了抢性能给文件加上 +C 属性关掉 CoW，系统会连带把校验功能一起停了。

在 2026 年做选型，单盘和双盘镜像已经成熟，单盘系统盘可以直接闭眼选。SUSE 早在 SLES 12（2014）起就把 Btrfs 和 snapper 自动快照配成了默认（SUSE 文档 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/e0hph7h7r96pw0i7u2/aHR0cHM6Ly9kb2N1bWVudGF0aW9uLnN1c2UuY29tL3NsZXMvMTUtU1A3L3NpbmdsZS1odG1sL1NMRVMtc3RvcmFnZQ== )）；Fedora 桌面版也在 F33（2020）时默认跟进（Fedora Change 页 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/owhkhqhwq3pklguqur/aHR0cHM6Ly9mZWRvcmFwcm9qZWN0Lm9yZy93aWtpL0NoYW5nZXMvQnRyZnNCeURlZmF1bHQ= )）。至于大厂基建，Meta 称它们靠全线跑 Btrfs 省下了数十亿美元成本（Phoronix ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/z2hghnhel9n4rwuzu0/aHR0cHM6Ly93d3cucGhvcm9uaXguY29tL25ld3MvQnRyZnMtU2F2ZXMtTWV0YS1CaWxsaW9ucw== )）。

但如果是五盘校验阵列，目前还是个没收工的工地。Btrfs 官方状态页至今仍把 RAID5/6 挂着 unstable 牌子，病根就落在 write hole 上。另一条替代路线 stripe tree 还缩在 CONFIG_BTRFS_EXPERIMENTAL 编译参数后面，磁盘格式都没定稿（官方 Status 页 ( https://0128b587.click.kit-mail3.com/lmu3evd75obmhndzzr0h6h8dg528rbgh4z2op/x0hph6heq8ordkfgul/aHR0cHM6Ly9idHJmcy5yZWFkdGhlZG9jcy5pby9lbi9sYXRlc3QvU3RhdHVzLmh0bWw= )）。内核稳定性上也有些插曲，比如 2025 年夏天 6.15.3 内核出现过断电后回放日志卡死的问题，修复最后拖到了 6.17 版本。
